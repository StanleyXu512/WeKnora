# 集团非结构化数据中台 Open API 功能与接口方案

版本：V0.1（接口范围讨论稿）  
日期：2026-10-11  
关联：总体架构方案第 8.5 节。  
说明：以下是目标接口契约建议，不代表 WeKnora 已实现的接口；URI、字段和认证实现待方案确认后固化为机器可读接口规范。

## 1. 开放目标与调用对象

Open API 将非结构化数据资产、标准加工结果和知识能力交付给集团数据门户、数据中台及下游业务系统。下游不需要直接读取对象存储、向量库或平台业务数据库。

支持两种消费模式：

- **系统消费**：以应用服务身份获取已明确授予该系统的数据产品，例如合同抽取字段和业务资料。
- **代用户消费**：门户、业务应用代表登录用户搜索或问答，平台同时校验应用范围和用户权限。

API 不默认允许下游修改源权限、管理全集团成员、修改集团强制规则或持有源系统凭据。平台管理接口与业务开放接口使用独立授权范围。

## 2. 推荐开放的能力

| 能力分组 | 功能 | 典型消费者 | 开放策略 |
| --- | --- | --- | --- |
| 资产目录与发现 | 空间/知识库目录、资产列表、元数据、业务关联、版本 | 数据门户、集团目录、业务系统 | 基础；目录可发现与正文可读分开 |
| 标准内容与文件 | 正文、表格、图片、章节、来源定位、预览、原件下载 | 文档应用、业务系统 | 基础；原件、预览、脱敏版本分别授权 |
| 知识检索 | 全文/语义/混合检索、条件筛选、指定资产范围 | 门户、业务应用、智能助手 | 基础；服务端权限过滤 |
| 结构化加工结果 | 业务字段、抽取模板、质量状态、数据产品与 Schema | 数据中台、合同/风控等业务系统 | 基础；仅提供允许发布的结果 |
| 智能问答 | 有据回答、引用、流式输出、会话管理 | 门户、业务应用、助手 | 按需；用户上下文及模型准入 |
| 变更与订阅 | 增量拉取、事件订阅、权限失效、交付回执 | 需要缓存/复制资产的系统 | 缓存或复制场景必需 |
| 处理任务 | 授权管道列表、提交处理、状态、报告、取消/重试 | 业务批处理系统 | 受控；与消费权限分离 |
| 数据提交与维护 | 上传、登记来源、更新自有资产、删除申请 | 经批准的生产者系统 | 受控；限定来源和资产归属 |
| 质量与反馈 | 质量报告、血缘、错误反馈、纠错建议 | 治理平台、业务系统 | 受控；反馈不直接覆盖权威结果 |
| 授权与使用管理 | 当前能力、权限申请、申请状态、配额和自身用量 | 门户、集成运维 | 仅限当前调用者可见范围 |

规则、模型、凭据、组织和平台全量审计管理不作为普通下游应用默认能力。Agent 执行、MCP、图谱和飞书写回作为另行批准的扩展契约。

## 3. 建议接口目录

基础路径示例：`/openapi/v1`。服务响应中包含当前可用的操作和链接，避免消费方凭路径猜测访问权限。

### 3.1 资产目录与发现

| 方法与路径 | 功能 | 核心约束 |
| --- | --- | --- |
| `GET /spaces` | 获取授权空间 | 不暴露无权发现的组织空间 |
| `GET /knowledge-bases` | 获取授权知识库 | 可按空间和业务主题筛选 |
| `GET /assets` | 分页查询资产目录 | 按组织、类型、标签、业务主键、更新时间筛选 |
| `GET /assets/{asset_id}` | 获取元数据及可用操作 | 目录发现权限只返回批准的元数据 |
| `POST /assets/lookup` | 按业务对象或源对象批量匹配资产 | 不允许通过匹配探测无权资源；逐项处理 |
| `GET /assets/{asset_id}/versions` | 获取允许访问的发布版本 | 历史版本需要独立可用性与权限检查 |

资产对象最少提供 `asset_id`、归属组织/空间、类型、业务关联、来源、当前发布版本、Schema 版本、有效状态和来源导航。敏感元数据按字段策略投影。

### 3.2 标准内容、预览与文件

| 方法与路径 | 功能 | 核心约束 |
| --- | --- | --- |
| `GET /assets/{asset_id}/content` | 获取发布正文、章节及来源定位 | 按版本、格式和脱敏策略选择；大型正文分页 |
| `GET /assets/{asset_id}/artifacts` | 获取允许读取的表格、图片等产物清单 | 清单仅列出可访问的产物与版本 |
| `GET /artifacts/{artifact_id}/content` | 获取具体产物内容 | 精确校验资产绑定、发布状态和当前权限 |
| `POST /assets/{asset_id}/access-links` | 创建受控预览/下载访问入口 | 指定用途和版本；原件下载单独授权 |
| `GET /assets/{asset_id}/files/{file_id}/download` | 通过鉴权代理读取文件 | 支持适合后端的流式下载及断点读取 |

签名链接仅在策略允许时生成，具有明确有效期；高敏文件优先使用鉴权代理。既不提供原始存储凭据，也不以任意文件路径参数获取内容。

### 3.3 检索

| 方法与路径 | 功能 | 核心约束 |
| --- | --- | --- |
| `POST /search` | 全文、语义或混合检索 | 支持空间/知识库/资产范围和元数据条件 |
| `GET /search/capabilities` | 获取允许的检索模式、过滤字段和上限 | 避免下游硬编码不可用能力 |

命中结果提供资产 ID、发布版本、分块/来源定位、授权片段、分数及原文入口。查询参数不能突破应用或用户范围；限制候选数、返回数和执行时间。默认只检索有效发布版本。

### 3.4 字段抽取结果与数据产品

| 方法与路径 | 功能 | 核心约束 |
| --- | --- | --- |
| `GET /assets/{asset_id}/extractions` | 获取按模板产生的字段结果 | 返回 Schema、处理版本、字段来源和复核状态 |
| `GET /data-products` | 列出授权数据产品 | 明确交付格式、字段、用途和更新方式 |
| `GET /data-products/{product_id}/schema` | 获取输出 Schema | 包括字段类型、业务含义、必填、脱敏和版本 |
| `POST /data-products/{product_id}/query` | 条件查询已发布标准结果 | 使用允许字段和算子的结构化条件，不开放任意 SQL |
| `POST /exports` | 创建受控批量交付任务 | 指定数据产品/范围、字段、格式与快照 |
| `GET /exports/{export_id}` | 获取交付状态和授权产物引用 | 下载时再次检查当前权限，失效后不可继续读取 |

抽取结果区分模型输出、校验通过和人工确认；用途要求复核的字段只有满足发布条件后可交付。API 返回值不把模型置信度当作事实正确性的保证。

### 3.5 智能问答

| 方法与路径 | 功能 | 核心约束 |
| --- | --- | --- |
| `POST /answers` | 单轮知识问答 | 指定授权知识范围，可选择流式响应 |
| `POST /conversations` | 创建下游专用会话 | 绑定应用、实际主体和空间；服务自动生成身份绑定 |
| `POST /conversations/{conversation_id}/messages` | 多轮问答 | 会话归属校验，每轮重新校验知识权限 |
| `DELETE /conversations/{conversation_id}` | 删除自有会话 | 按留存和审计政策处理 |

输出包括回答、证据是否充分、引用、实际使用的资产发布版本、请求 ID 和允许披露的用量。不向普通消费者暴露系统提示词、内部推理或其他用户会话。历史回答可能含已失权来源，重新展示时按当前策略遮蔽或阻止读取相关内容；已交付的外部副本另按消费契约管理。

### 3.6 增量变更与订阅

| 方法与路径 | 功能 | 核心约束 |
| --- | --- | --- |
| `POST /sync-snapshots` | 创建授权范围的同步基线 | 固定快照及对应变更水位，避免全量与增量之间丢数据 |
| `GET /sync-snapshots/{snapshot_id}/assets` | 分页读取基线清单 | 在读取时复核授权；同时提供基线处理状态 |
| `GET /changes` | 按游标拉取变更 | 事件包含更新、失效、删除和权限变化 |
| `POST /subscriptions` | 创建事件订阅 | 固定授权范围、过滤条件和受控回调地址 |
| `GET /subscriptions/{subscription_id}` | 查询自有订阅状态 | 提供交付水位、失败和授权变化状态 |
| `PATCH /subscriptions/{subscription_id}` | 修改/暂停自有订阅 | 扩大范围时重新授权并要求新的基线 |
| `DELETE /subscriptions/{subscription_id}` | 取消订阅 | 不替代对已经交付副本的失效处理 |
| `POST /deliveries/{delivery_id}/ack` | 反馈已应用或失败状态 | 撤权/删除回执明确下游应用结果 |

事件至少包含 `event_id`、类型、资产/发布/权限版本、序号、时间和受控读取引用。采用至少一次交付、签名验证、重放保护、失败重试和对账机制；顺序只在约定分区/对象范围内保证。

**撤权事件不能仅按“当前仍可读”过滤**：平台保留该消费者此前交付的最小对象记录，对已失权对象发送只包含必要 ID 和处置类型的失效通知，不能附带已无权读取的标题或正文。全范围失权时使用范围失效信号并要求消费者撤回对应副本。

新增授权时提示重新建立新增范围基线，不能仅发送内容变更，否则未变更的历史资料会遗漏。游标过期明确返回重新建立基线要求。消费者遵循快照—增量协议并定期对账，不能以 Webhook 成功送达代替状态一致性。

### 3.7 处理服务与任务

| 方法与路径 | 功能 | 核心约束 |
| --- | --- | --- |
| `GET /processing/pipelines` | 获取允许调用的管道及参数 Schema | 不返回平台内部凭据和敏感规则配置 |
| `POST /processing/jobs` | 提交单个或批量加工任务 | 仅允许授权管道和参数，固定输入版本 |
| `GET /processing/jobs/{job_id}` | 查询进度和逐项状态 | 绑定提交应用/主体，不允许枚举他人任务 |
| `GET /processing/jobs/{job_id}/report` | 获取质量、成功失败和产物报告 | 技术日志与对外错误信息分离 |
| `POST /processing/jobs/{job_id}/cancel` | 请求取消任务 | 返回取消状态；不承诺即时停止外部步骤 |
| `POST /processing/jobs/{job_id}/retry` | 重试符合条件的失败对象 | 重新鉴权，记录执行尝试并保持幂等 |

能读取资料不等于能提交任意加工，更不等于能发布结果。`processing:execute` 与 `publication:request` 分开，发布策略不能由调用方参数绕过。

### 3.8 受控数据提交与维护

以下面向已登记的生产者系统，普通只读下游默认不授予。

| 方法与路径 | 功能 | 核心约束 |
| --- | --- | --- |
| `POST /uploads` | 创建上传会话 | 校验类型、大小、来源归属和上传配额 |
| `POST /uploads/{upload_id}/complete` | 完成上传并校验内容 | 不因上传完成自动公开或发布 |
| `POST /ingestions` | 登记源对象并提交入库 | 引用上传对象或批准来源，包含源版本及业务元数据 |
| `GET /ingestions/{ingestion_id}` | 查询接入状态 | 只返回本应用有权查看的对象 |
| `PATCH /assets/{asset_id}/metadata` | 修改允许维护的业务元数据 | 字段白名单、源权威关系和版本冲突检查 |
| `POST /assets/{asset_id}/deletion-requests` | 请求删除/停用自有来源资产 | 保留政策和必要审批，不提供默认硬删除 |

不得通过入库请求伪造其他系统的来源和权限。源权限变更只接受登记的权威来源或专用治理接口；任意 URL 拉取仅限批准来源，避免开放任意网络访问代理。

### 3.9 质量、血缘、反馈与授权

| 方法与路径 | 功能 | 核心约束 |
| --- | --- | --- |
| `GET /assets/{asset_id}/quality` | 查询发布质量和复核结果 | 不泄露禁止读取的原文值 |
| `GET /assets/{asset_id}/lineage` | 查询授权血缘视图 | 未授权上游节点裁剪或隐藏 |
| `POST /feedback` | 提交问答、字段或资产质量反馈 | 关联引用版本，进入审核闭环 |
| `GET /me/capabilities` | 查询当前应用/主体能力 | 不提供全集团权限枚举 |
| `POST /access-requests` | 发起资源访问申请 | 交由指定权威审批流程处理 |
| `GET /access-requests/{request_id}` | 查询本人/本应用申请状态 | 与实际授权结果分离，审批后仍校验策略 |
| `GET /me/usage` | 查询自有配额、调用和任务用量 | 平台全量审计不对普通消费者开放 |

## 4. 认证与授权契约

### 4.1 应用注册与凭据

每个下游登记独立应用，记录责任人、允许来源网络、用途、组织/数据范围、接口能力、配额、凭据生命周期及订阅地址。

认证优先对接集团应用身份/令牌体系；可采用面向应用的短期令牌。若使用 API Key，同样绑定范围、有效期和轮换机制，不能使用管理员个人令牌作为永久系统凭据。

### 4.2 代用户与系统身份

- 系统调用按明确授予的系统数据范围授权，不借用后台服务账号读取所有空间。
- 代用户调用使用可验证且绑定当前应用的用户委托令牌；实际权限是应用范围与用户当前权限的交集。
- 用户 ID、组织 ID 或客户端自报角色只作为参数，不构成授权证据；会话和异步任务保留验证过的主体绑定。

### 4.3 权限范围示例

`catalog:read`、`content:read`、`preview:read`、`file:download`、`search:execute`、`extraction:read`、`answer:execute`、`events:subscribe`、`processing:execute`、`asset:ingest`、`metadata:write`、`export:create`。

能力授权之外仍检查资源范围、密级、来源、有效期和当前策略。对范围参数只允许缩小选择，不允许突破授权；API 所有产物、导出和引用适用同样约束。

## 5. 通用接口规范

- **版本**：API 版本、数据 Schema 版本、源版本、发布版本和权限版本分开；破坏性变更通过新契约发布并公告兼容期。
- **响应**：包含 `request_id`；列表采用不透明游标和上限。成功数据提供资源与发布版本，错误提供稳定错误码及是否适合重试。
- **状态**：区分认证失败、权限不足、不存在/不可披露、版本冲突、限流和依赖异常；不通过错误差异泄露无权资源的存在。
- **幂等**：提交、导出、任务等接口支持 `Idempotency-Key`，按应用与操作绑定规范化请求摘要；相同键不同请求拒绝，不重复创建任务。
- **并发**：元数据更新和发布请求使用预期版本或 ETag 条件，旧请求不能覆盖新结果。
- **异步**：耗时接入、批处理、导出返回接收状态及任务 ID；支持轮询、事件和取消；任务结果读取仍重新鉴权。
- **一致性**：明确接口交付的发布快照与水位，不承诺多个异步系统在同一瞬间更新。
- **限流与成本**：按应用、组织、能力和模型用量设置额度，提供限流响应及重试信息；检索与问答不与大批次共享无限制资源。
- **事件安全**：回调地址登记并校验，使用签名、时间戳和事件 ID；凭据不放 URL，事件不携带敏感正文。
- **审计**：记录调用主体、用途、资源、动作、结果和请求 ID；不记录密钥或未经允许的正文。
- **开发者支持**：提供接口规范、字段字典、示例、沙箱样本、错误码、认证指南及变更通知；测试环境使用独立凭据和数据。

## 6. 三种典型调用闭环

### 6.1 数据门户：发现、申请、检索与问答

验证应用与用户委托 → 查询可发现目录 → 对未授权资产发起申请 → 授权后检索/问答 → 获取引用与允许的预览入口 → 访问时再次鉴权。

### 6.2 数据中台：消费合同抽取数据

登记系统消费范围 → 获取合同数据产品 Schema → 建立同步基线 → 获取已复核字段 → 增量接收发布/失效事件 → 按合同业务主键入库 → 回执与定期对账。

### 6.3 业务系统：提交资料并调用加工

取得生产者与处理权限 → 上传/登记源资料 → 调用允许的管道 → 查询批次报告 → 等待发布条件完成 → 获取标准结果 → 接收更新、撤权和删除通知。

## 7. 接口验收要点

1. 不同应用、用户、组织和数据范围交叉调用时，目录、内容、引用与文件均不越权。
2. 同一请求重试不产生重复接入、任务或导出；旧版本更新返回冲突。
3. 同步基线与增量衔接不丢更新；游标过期有明确恢复路径。
4. 下游失去读取权限后仍收到必要失效信号，但不继续收到受限内容。
5. 异步结果和导出创建后发生撤权，后续结果读取和下载被拒绝或按批准策略限制。
6. 模型问答与处理不能突破模型准入、输入范围、成本配额和发布政策。
7. 下游权限不足、限流、任务失败、部分成功和撤销失败均具有可定位且不泄密的状态。

## 8. 方案确认项

- 下游消费者清单及对应能力：只读、缓存复制、加工调用还是资料生产。
- 系统身份与代用户身份分别采用的集团认证方式。
- 可交付的数据产品、字段、原件、脱敏结果及用途限制。
- 是否需要流式问答、多轮会话、批量导出和任务回调。
- 同步与撤权时限、事件通道、回执及副本处置责任。
- API 版本兼容期、各能力配额、响应和吞吐指标。

以上是完整能力边界，不是实施排期。具体开放集合应按消费场景授权，不能给每个下游默认授予全部接口。
