# S0 设计契约草案

状态：目标设计，尚未实现；不是当前 WeKnora API 的能力声明。

## 1. 主体与权限

集团组织表达行政归属，空间表达协作边界，资产表达知识归属。组织上级关系不自动授予正文权限；平台运维角色也不自动获得业务正文读取权。

读取决策需要同时满足：有效主体、应用范围（系统调用时）、资产策略、源权限约束、当前发布/停用状态。无源 ACL 的上传资料使用明确的上传归属与资产策略；有源 ACL 的资料必须记录校验状态和时间。权限无法映射或过期时按批准的新鲜度策略限制访问，不能因为采集账号可读而放宽用户权限。

管理、元数据发现、正文阅读、原件下载、加工、发布、共享分别授权。服务任务使用限定输入/输出的执行身份，不能继承平台管理员的无限范围。

| 案例 | 条件 | 目标结果 |
| --- | --- | --- |
| 同组织读取 | A 用户在允许空间；资产有效且已发布 | 可检索、问答及读取已授权正文 |
| 同组织无授权 | 同属 A，但不在该资产授权范围 | 拒绝；组织归属本身不足以允许 |
| 跨组织默认 | B 未获共享 | 不返回正文、片段或可推断内容的引用 |
| 跨组织共享 | B 获显式授权，源权限也允许 | 只开放指定操作及期限 |
| 源权限拒绝 | 集团共享允许，源 ACL 拒绝 | 拒绝；共享不能扩大源授权 |
| 飞书采集账号可读 | 用户源身份不能映射 | 不能直接给该用户阅读权限 |
| 平台运维 | 可管理运行环境，未获正文授权 | 管理入口按授权开放；正文仍拒绝 |
| 用户离职/撤权 | 会话和缓存曾经有效 | 新读取拒绝；历史检索和引用重新检查 |
| 下游系统代用户 | 应用有效，用户身份经过可信验证 | 应用范围与用户权限取交集 |
| 加工任务 | 仅获指定版本输入和产物写入权限 | 禁止读取其他资产或自行发布 |
| 派生汇总 | 汇总引用多份源资料 | 按可追溯来源限制；不能借汇总泄露受限资料 |

覆盖出口：目录、正文、原件、分块、图片、检索、Agent 工具、问答引用、会话历史、导出、Webhook 和共享链接。已经交付到外部系统的数据无法仅靠中台技术保证被收回，下游须实现失效回执和副本清理约定。

## 2. 核心数据模型

字段为逻辑契约；物理表名、字段类型和索引在适配验证后确定。

| 对象 | 核心字段 | 约束 |
| --- | --- | --- |
| Asset | asset_id、owner_org_id、space_id、responsible_party、classification | 集团资产 ID 稳定，不使用 WeKnora knowledge_id 作唯一业务标识 |
| SourceBinding | connector_id、source_tenant、source_object_id、asset_id | 来源复合身份唯一；不能只按文件名去重 |
| AssetVersion | asset_version_id、source_revision、content_hash、raw_ref、captured_at | 原始版本不可变；同内容不代表源权限相同 |
| PolicyBinding | asset_id、policy_revision、source_acl_revision、checked_at | 权限版本独立于内容版本；支持纯权限变更 |
| RuleVersion/PipelineVersion | version_id、definition_hash、operator_versions | 已执行版本不可修改；强制规则不能被下层覆盖 |
| TaskAttempt | task_id、attempt_id、input_snapshot、rule_version、execution_identity | 重试保留同一输入快照；新规则应启动新任务 |
| Artifact | artifact_id、input_version、kind、object_ref、checksum、source_locator | 正文、表格、图片、抽取字段保留来源定位 |
| QualityResult/LineageEdge | artifact_id、check_version、result；from_id、to_id | 质量结果有阈值和证据；血缘关联到具体版本 |
| Publication | publication_id、manifest、index_generation、expected_previous、state | 只切换准备完成且策略有效的版本；并发条件更新 |
| Delivery/Event | event_id、publication_id、policy_revision、subscription_id、sequence | 至少一次交付；接收方按事件 ID 幂等；支持失效回执 |
| WeKnoraMapping | asset_id、publication_id、tenant_id、kb_id、knowledge_id | 支持一个资产多版本及撤销旧映射；内部实现引用 |

Raw 是原始快照，Curated 是加工产物，Serving 是已发布消费视图。三者可使用同一对象存储的不同前缀或桶，逻辑隔离仍需应用授权，不能仅依靠对象路径命名。

## 3. 状态与并发行为

- 接入：发现 → 获取 → 原始版本登记。单次 403/404 或局部目录失败不自动判定删除。
- 加工：排队 → 执行 → 成功/失败/取消；复核状态独立记录。批次报告逐资产统计，不以批次成功掩盖部分失败。
- 发布：待复核 → 已批准 → 索引准备 → 可切换 → 生效/失败/撤销。加工成功不等于发布生效。
- 撤权：授权事实更新并阻断出口 → 发失效事件 → 清理索引/缓存/副本 → 收集回执及对账。
- 新版本发布采用 expected_previous 或等价条件更新。旧任务迟到不能覆盖当前版本；取消后迟到结果不得发布。
- 保留上一有效版本仅用于正常发布失败恢复；撤权或停用后不能回退到仍泄露内容的旧版本。

## 4. 内部执行与发布契约

加工请求固定：task_id、attempt_id、asset_version_id、输入清单、rule/pipeline_version、输出规范版本、执行身份、截止时间。不得允许客户端任意指定未授权对象路径或代码执行。

加工结果返回：成功/失败/待复核、产物清单、校验和、字段抽取、质量报告、来源定位、算子与模型版本、耗时及错误类型。成功返回不能直接改变生产发布指针。

发布请求固定 publication_id、输入/产物版本、批准记录、目标范围、expected_previous。适配层返回 WeKnora 映射、索引代次、就绪状态和失败原因。只有索引与授权条件满足，集团发布视图才可生效。

幂等键按调用主体和操作域隔离；同键不同请求摘要应报冲突。重试不能造成重复资产、重复索引或重复发布切换。

## 5. 首批外部契约切片

以下为集团目标接口，路径参考总体 Open API 草案，在契约冻结前不作为可调用地址。

| 切片 | 输入/输出重点 | 异常行为 |
| --- | --- | --- |
| 接入登记与任务状态 | 来源身份、内容摘要、版本、幂等键；任务及逐项结果 | 重复提交复用结果；身份不符拒绝 |
| 授权目录及资产详情 | 用户/系统身份、游标、投影；允许的元数据 | 不返回越权资产或敏感字段 |
| 检索与问答 SSE | 发布范围、会话归属；答案、引用、完成/错误事件 | 当前权限改变时停止泄露；取消和连接中断有约定 |
| 抽取结果/文件读取 | 指定产物或发布版本；结构化结果或受控下载 | 旧链接与旧授权不能绕过当前策略 |
| 同步基线及增量 | 快照、水位、事件 ID、顺序和回执 | 新授权补基线；丢事件可对账；失权发送最小失效通知 |

每个切片还需冻结身份协议、Schema、错误码、版本冲突处理、超时、配额和兼容策略。集团中台权威字段与本平台自有字段分开，避免双向覆盖。

## 6. 三个飞书租户与统一身份

连接主键使用 connector_id + source_tenant；来源对象主键包含租户和对象类型，避免不同租户的对象 ID 碰撞。配置、凭据、应用授权范围、同步游标与故障状态分别记录，不共享访问令牌。

身份映射记录集团 person_id、飞书 tenant_id、租户内用户标识、映射依据、状态和有效期。飞书具体标识选择及跨应用稳定性需要结合应用配置验证。未映射用户不能通过名字或手机号猜测授权。

组织和人员归属以集团主数据为权威；飞书主体与 ACL 保留来源事实。用户调岗、离职、飞书移除成员、资产共享到期分别触发策略刷新，不能只在内容更新时检查权限。

新增验证：三个租户各接入一份制度；同人多账号；同名不同人；不同租户同对象 ID；一个租户不可用；跨租户共享允许/拒绝；主数据离职后旧飞书账号仍存在。预期均以当前集团主体状态、源 ACL 和资产策略共同判断。

## 7. 飞书后台配置

此节为已确认的建设方式，尚未实现该集团配置界面。后台入口建议为“系统管理 → 数据源 → 飞书”，以租户连接列表管理三个租户，数据结构支持后续增加租户，不把租户数量写死。

| 配置区 | 字段或操作 | 约束 |
| --- | --- | --- |
| 租户连接 | 名称、来源租户标识、连接 ID、启停状态、责任人 | 业务组织通过显式映射关联，租户不直接等于集团组织 |
| 应用凭据 | App ID、App Secret 或凭据引用、更换凭据 | 密文保存，接口不回传明文；空值保存不覆盖已有凭据；不向日志输出 |
| 授权检查 | 测试连接、权限检查、授权状态与错误提示 | 飞书侧应用权限仍需管理员授权；验证支持的授权模式 |
| 采集范围 | 文档/云盘/知识库、允许目录或节点、目标空间 | 只采集配置且有权访问的范围，不能默认全租户开放 |
| 同步计划 | 时区、执行时间/周期、增量与对账策略、手动触发 | 与每日组织人员导入计划分开配置；同连接重复触发需去重 |
| 身份与权限 | 租户账号映射、源 ACL 策略、权限校验时间 | 凭据有权采集不等于员工有权阅读；失败不能放宽授权 |
| 运行记录 | 批次、进度、成功/失败数、水位、失败原因、重试 | 三个租户独立运行和恢复，失败不推进该项水位 |

只有获得数据源管理授权的管理员可更改连接及凭据；组织管理员仅管理获授权的连接/范围。密钥只能新增或替换，详情和列表仅显示已配置状态；查看任务记录与修改凭据分开授权。配置变更记录操作者、时间和变更摘要，不记录秘密值。

配置每次保存形成版本，运行任务绑定配置快照。修改采集范围、组织映射或源权限策略需要重新评估已有资产；禁用同步默认只停止采集，不默认为撤销既有发布。停用知识服务或撤销授权应提供独立、明确的操作。

验收包括：三个租户分别配置和测试连接；凭据不泄露；无权用户不可改配置；定时和手动同步可追踪；单租户故障不影响其他租户；配置变更不使旧任务扩大范围；缩小范围后的已有资产处置可核对。

## 8. 每日组织人员导入与后续 OAuth2

导入契约包含批次 ID、全量/增量标记、完整性标记、组织/人员稳定 ID、成员关系、状态及可用的飞书账号映射。字段映射、导入来源与格式待确认。按批次校验后生效，错误逐项可查；明确停用记录立即按导入结果更新策略，不以不完整批次的缺失记录推断离职。

账号记录分别保留本地账号 ID、集团 person_id 与后续认证主体映射。OAuth2 接入时验证现有账号绑定，避免重复账号；具体认证协议及用户信息获取契约后续确认。初期不要求实时身份同步，但需紧急人工停用入口，并明确每日导入的权限变更延迟。
