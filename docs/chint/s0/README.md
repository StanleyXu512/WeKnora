# CHINT S0：设计与适配验证包

日期：2026-10-11  
状态：已启动；设计草案和源码证据已整理，业务确认与运行验证尚未完成。  
关联：[开发计划](../../CHINT_DEVELOPMENT_PLAN.md)、[总体架构](../../GROUP_UNSTRUCTURED_DATA_PLATFORM_ARCHITECTURE.md)、[需求](../../GROUP_UNSTRUCTURED_DATA_PLATFORM_REQUIREMENTS.md)、[Open API](../../GROUP_UNSTRUCTURED_DATA_PLATFORM_OPEN_API.md)。

## 1. S0 要解决的问题

S0 把总体方案转成可开发、可验收的边界。它完成后，应能回答：谁的资料由谁管理、哪些人能看、如何接入和加工、怎样发布给 WeKnora、下游怎样消费，以及社区升级时需要维护哪些改动。

不以页面数量或文档数量判断完成。关键链路必须有样本、预期结果及验证证据，未确认事项不能默认为已支持。

本阶段工作对应 D01—D05，并明确 F01 的构建前置条件。组织人员底座第一批代码已开始实现，详见 [开发说明](../DIRECTORY_DEVELOPMENT.md)；业务确认与 S0 验收继续进行，未修改用户现有模型配置或部署。

## 2. 首个验证闭环

采用两个虚构组织 A、B，业务样板已确认采用制度与操作规程，真实试点组织待确认。合成样本可以验证技术机制，不能替代真实业务验收。

```mermaid
flowchart LR
    S[上传或飞书来源] --> R[原始版本与源权限]
    R --> T[固定规则版本加工]
    T --> Q[质量检查与复核]
    Q --> P[发布清单与索引适配]
    P --> W[WeKnora 检索与问答]
    P --> D[下游接口与订阅]
    A[当前授权决策] --> W
    A --> D
```

验证过程：A 接入一份资料 → 加工 → 审核 → 发布 → A 检索问答 → B 默认拒绝 → 授权 B → B 可用 → 撤权 → B 的新读取及历史引用访问被拒绝，下游收到最小失效通知。

随后用资料更新、加工失败、事件重放、迟到任务和权限变化验证异常路径。仅在成功路径返回答案，不足以通过 S0。

## 6. S0 完成门槛

- 业务样板、身份权威来源、资产责任人与共享规则已确认。
- 上传及飞书代表性样本具备合法测试授权，内容和权限行为可验证。
- 导入、加工、索引、检索、引用的职责划分已验证，重复加工问题有结论。
- 资产级权限与撤权在关键出口上的改造范围已明确。
- 版本、幂等、发布和事件契约经过异常路径评审。
- 源码构建基线与运行版本对应关系有证据，回归入口明确。
- 未通过的事项有明确风险、责任人和后续安排，不伪装为已验收。

S0 当前仍处于设计和源码核对阶段。下一项技术工作是建立匹配源码的隔离验证环境，运行标准正文导入及权限验证；真实集团和飞书验证依赖上表的外部输入。

## 7. 本轮已确认条件的设计影响

业务样板为制度与操作规程。样本需覆盖制度编号、适用组织、生效日期、废止/替代关系及操作规程章节；哪些字段必填、如何判定有效版本，由业务责任人确认。问答需要区分有效制度与历史版本，不能仅依据向量相似度判断适用性。

组织人员主数据通过每天定时导入同步，使用稳定的人员与组织 ID；前期沿用本地登录并关联集团人员 ID，OAuth2 登录集成后补，不作为前期组织权限开发的阻塞项。导入失败或不完整批次不能按缺失人员直接判定离职；保留紧急停用和撤权入口。每日同步存在变更传播延迟，具体导入时间、异常处理及人员状态字段待确认。

飞书采用三个租户，连接配置、凭据引用、水位、来源对象和源 ACL 均带租户维度。同一人员可关联多个飞书租户身份；映射必须有可信依据，不能只用显示名匹配。一个租户的采集失败不应推进其他租户的失败对象水位。

下游未确定时先定义消费方契约和模拟客户端，不虚构已完成的系统集成。首个真实下游选定后，再验证身份委托、SSE、订阅回执和撤权副本处理。

飞书接入通过后台配置管理，三个租户分别登记、授权和运行。后台配置功能的字段、权限和验收要求见 [设计契约第 7 节](./DESIGN_CONTRACTS.md)。后台配置不能替代飞书侧管理员的应用授权。
