## 3. 加工职责的候选方案

| 方案 | 中台负责 | WeKnora 负责 | S0 判断方式 |
| --- | --- | --- | --- |
| A：标准正文导入 | 原件、解析/清洗/脱敏/抽取、质量、血缘 | 标准正文后续分块、Embedding、索引、问答 | 先验证已有 Markdown 入口；确认可禁用重复业务加工并保留引用 |
| B：标准分块导入 | A 的能力及业务分块 | 分块入库、Embedding、索引、问答 | 评估新增受控导入契约，禁止通过直接写上游表绕过服务约束 |

优先验证 A，尚未选定最终方案。若图片、表格、原页引用或分块质量无法满足业务要求，再评估 B。中台结构化抽取结果不必全部变成 WeKnora 知识，允许作为独立数据产品交付。

## 5. 样本准备清单

每份资料记录：样本 ID、业务类别、格式、合法测试范围、组织归属、源权限、原始版本、预期正文/表格/字段、来源定位、质量阈值及允许消费主体。

初始准备：一份制度正文、一份含表格/图片资料、一份扫描件、一份内容修订、一组源 ACL 变化、一份无权限样本、一组同名不同来源资料。先使用合成资料；真实资料需由责任人指定测试范围。

## 6. 升级维护边界

独立集团模型与迁移、执行服务、外部连接器和 Open API 适配层优先独立组织；上游核心补丁记录触点、原因、对应回归和是否可贡献社区。

每次升级先比较源码和数据库迁移，在隔离环境运行上述回归，再评估合并和部署。无法保证永远没有 Git 冲突；也不能用“合并成功”代替业务、权限与数据兼容验证。
