# 集团知识中心与非结构化数据中台需求说明书

版本：V0.4（需求讨论稿，补充多模态执行引擎集成）
日期：2026-10-11  
用途：业务需求梳理、范围确认及后续方案设计；不作为已确认的实施承诺。

## 1. 项目定位

建设集团级知识中心，以非结构化数据中台为基础，让集团内各组织管理自身知识资产，并通过统一的数据接入、处理、治理和服务能力，连接集团数据中台、数据门户及上下游业务系统。

平台既服务人员的知识管理和使用，也服务系统间的数据交换。知识库、搜索、智能问答属于面向用户的应用层；底层需要形成可复用的非结构化数据资产、处理管道、权限和服务接口。

### 1.1 已明确的需求

- 服务范围为集团及集团内各组织。
- 各组织可以管理自己的知识。
- 需要集成集团数据中台、数据门户和上下游系统。
- 需要集成飞书文档，包括云文档与知识库资料接入。
- 需要明确面向下游系统的 Open API 能力与调用契约。
- 需要非结构化数据 ELT 能力。
- 整体目标是建设非结构化数据中台。

### 1.2 本稿工作假设

以下为讨论建议，尚待确认：

- 集团采用共享平台，各组织拥有独立管理边界；物理隔离方式另行评估。
- 源业务系统和集团统一身份平台继续作为相应业务数据、身份的权威来源。
- 原始资料先进入受控原始区，再按照规则加工，形成标准内容与服务索引。
- 当前先确认完整方案架构，建设优先级、排期和技术实现待方案确认后讨论。
- WeKnora 是候选二开基础，需要补充中台能力，选型尚未定案。

## 2. 建设目标与边界

### 2.1 建设目标

1. **组织自治**：各组织自主接入、维护、处理和发布自身知识。
2. **集团治理**：集团建立统一分类、元数据、安全、质量及共享标准。
3. **数据贯通**：与已有中台和门户交换目录、身份、元数据及服务，而非形成新的孤立资料库。
4. **统一加工**：将多种格式和来源的资料加工为可检索、可追溯、可交换的标准内容。
5. **资产复用**：通过门户、搜索、API、订阅和智能应用消费知识资产。
6. **全程可追溯**：记录来源、版本、处理规则、质量结果、权限变化和下游分发状态。

### 2.2 范围边界

本项目负责非结构化数据接入、存储、加工、治理和服务。与结构化数据通过业务主键、目录及接口关联。

首期不默认重建现有结构化数据仓库、主数据平台、统一身份平台或业务系统的审批流程；需要建设的新增审批以知识发布、共享和权限申请为主。是否纳入实时音视频、独立 BI、复杂 Agent 自动执行，应单独确认。

## 3. 用户、组织与职责

### 3.1 组织模型

- 支持集团—子集团/事业部—公司—部门等多级组织；实际层级以集团组织体系为准。
- 区分“行政组织”“知识空间”“项目/协作组”，允许一个组织管理多个空间，用户参与多个空间。
- 每项知识资产记录归属组织、责任人、维护人及来源系统。
- 支持集团公共知识、组织内部知识及跨组织授权知识。
- 支持组织新增、撤并、成员调动、离职及资产移交；组织树上下级关系不自动代表可读取全部内容。

### 3.2 角色建议

| 角色 | 职责 |
| --- | --- |
| 集团平台管理员 | 系统配置、组织接入、服务运行、平台运维 |
| 集团数据治理人员 | 元数据、分类、质量、安全和共享标准管理 |
| 组织管理员 | 管理本组织空间、成员、连接器和资产管理规则 |
| 数据/知识责任人 | 对资产质量、权限、有效性和发布负责 |
| 知识维护人员 | 上传、修订、处理及维护授权范围内的资料 |
| 普通使用者 | 检索、阅读、问答及按权限下载知识 |
| 系统服务账号 | 按接口权限接入、查询或订阅数据 |

平台运维权限与内容读取权限应分离。角色模板、权限继承和例外授权需要另行确认。

## 4. 总体业务流程

```text
集团身份与组织 / 源系统数据及权限 / 集团分类与主数据
                         ↓
                 连接器接入、变更识别
                         ↓
       原始区：原文件、源元数据、源权限、版本、校验值
                         ↓
       规则处理：解析 → 清洗 → 脱敏 → 抽取 → 分类 → 校验
                         ↓
      标准内容区：正文、表格、图片、字段、来源定位、血缘
                         ↓
         按规则发布：目录、全文/向量索引、知识页面、API
                         ↓
      集团门户 / 数据中台 / 知识应用 / 下游业务系统
```

各阶段共同受权限、质量、审计、生命周期和任务状态管理约束。发布到门户与开放接口前，需要满足资产的发布策略。

## 5. 核心功能需求

### 5.1 多组织知识管理

- 提供集团与组织工作台，展示授权范围内的资产、处理任务和质量情况。
- 支持空间、知识库、目录、文档、标签及业务主题的管理。
- 支持批量上传、目录保留、版本维护、归档、移交及失效管理。
- 支持草稿、待审核、已发布、已停用等业务状态；与解析成功/失败等技术状态分开。
- 支持组织共享申请、审批、期限设置及撤销；集团发布标准与组织流程可配置。
- 同一资料跨组织引用时保留源归属及权限，复制或导出属于独立受控操作。

### 5.2 数据接入与系统连接

接入方式包括人工上传、对象存储/文件目录、系统 API、数据库中的附件与元数据、事件消息及按需网页采集。具体连接器以集团系统清单为准。

- 连接配置包含组织、来源系统、访问凭据、数据范围、同步周期、增量标识及权限映射。
- 支持全量初始化、定时增量、事件触发、手工补采、暂停和恢复。
- 识别新增、修改、删除和权限变更；无增量能力的源系统采用对账机制。
- 使用来源系统标识、源对象 ID、版本及内容校验值进行去重和幂等处理。
- 记录采集时间、水位、失败对象和重试结果，支持差错补偿与源端对账。
- 对没有提供完整权限的来源，使用经批准的权限策略，不默认集团内公开。

### 5.2.1 飞书文档集成

飞书作为明确的知识来源，提供独立连接器配置及同步状态；与飞书机器人问答属于不同功能。

- **接入范围**：飞书云文档、云盘指定文件夹及知识库指定空间/节点；电子表格、多维表格和附件按业务需要与 API 能力确认。聊天记录不因文档集成自动纳入。
- **组织管理**：支持各组织选择自己的接入范围，绑定飞书租户、应用与目标知识空间；集团如存在多个飞书租户，分别管理身份和凭据。
- **内容采集**：获取标题、正文结构、表格、图片/附件、来源链接及可获得的源元数据；保留知识库树、文档关系与来源标识。
- **原始留存**：在线原生文档保存 API 返回的结构化内容快照及采集信息；源端提供且允许导出的文件另行留存，不假定每个文档都有可下载原件。
- **同步机制**：全量初始化、定时增量、可用事件触发和周期对账；识别内容更新、目录移动、重命名、删除与权限变化。事件覆盖范围需验证，不能只依赖事件实现撤权。
- **身份与权限**：映射飞书用户、部门和协作者到集团主体；文档、文件夹及知识库约束共同参与授权判断。应用能够采集文档不代表所有平台用户能够读取。
- **失效处理**：撤权或删除后限制平台访问并传播至检索、问答、派生产物和下游；超时、限流或单次不可访问不直接判定为已删除。
- **知识消费**：支持回跳飞书原文；可选嵌入预览须验证原端登录和权限，不通过平台服务账号代用户绕过源权限。
- **写回边界**：本稿默认单向采集与原文回跳；向飞书发布加工结果属于可选独立能力，需确定目标空间、审批、写权限和冲突策略，不默认改写源文档。
- **接入前提**：由集团明确飞书应用管理员、授权主体、可接入范围、凭据管理、接口权限及源内容负责人。

### 5.3 非结构化 ELT

采用 **Extract → Load → Transform**：先抽取并保留原始资料，再执行加工。原始区受访问和保留策略控制，不能因保留原件绕过脱敏要求。

| 阶段 | 需求 |
| --- | --- |
| Extract 抽取 | 采集内容、元数据、附件关系、版本及源权限 |
| Load 原始装载 | 原始资料可校验、可版本化、可回放；大文件与数据库元数据分开存储 |
| Transform 转换 | 按格式和业务规则解析、清洗、OCR、脱敏、抽取、分类、分块及质量校验 |
| 加工结果发布 | 生成标准内容、检索索引和服务输出；记录结果与原件、规则的关联 |

目标格式包含 PDF、Office、文本、HTML、图片及表格；音频、视频、压缩包和专业格式按业务优先级纳入。

处理能力包括：

- 提取正文、标题层级、表格、图片及页码/坐标等来源定位。
- 文本编码与格式规范化，去除页眉页脚等噪声；保留修改记录。
- 重复识别、敏感信息检测、脱敏及必要的人工复核。
- 依据字段模板抽取合同、制度、报告等业务信息；输出 JSON/表格等约定格式。
- 映射集团分类、主数据和业务对象，形成元数据及关联关系。
- 配置分块、摘要、标签、问答生成、向量化及可选图谱/Wiki 加工。
- 解析失败、质量不足或风险命中的资料进入待处理区，不自动发布。

### 5.3.1 多模态执行引擎扩展

- 提供执行后端适配机制，允许按任务接入普通 Worker、Ray Data、Vane Data 等候选引擎；具体选型和用户所指 Vane 项目待确认。
- 多模态加工可覆盖图片/OCR、音频转写、视频抽帧与时间定位、表格处理及模型抽取；具体可用范围依赖算子与模型，不仅取决于执行引擎。
- 支持 CPU/GPU 资源声明、组织预算、模型准入、任务进度、失败恢复及取消，并统一返回标准产物和血缘。
- 执行引擎与集团组织、权限、规则、质量和发布解耦；不能让引擎直接绕过发布门槛或对外开放任意执行。
- 下游使用稳定 Open API，不依赖内部执行产品；Ray Data 与 Vane Data 不默认必须同时使用。
- 引擎性能、版本、资源、失败恢复与权限隔离使用真实样本验证，不能直接套用单节点厂商基准。

### 5.4 统一规则与批处理

集团维护规则模板，组织在授权范围内选择、继承或覆盖。强制安全规则不可由组织关闭。

每个规则应具备 ID、版本、适用范围、优先级、输入/输出约束、责任人和生效状态。规则范围可以按组织、来源、资料类型、标签和元数据筛选；冲突时应有明确的合并或优先策略。

- 区分确定性规则与模型规则。格式校验、字段约束等优先采用确定性处理；语义分类、摘要等可以采用模型。
- 模型规则记录模型版本、提示词版本和参数；输出需校验，关键字段支持人工复核。
- 提供管道配置，将多个处理步骤组成可复用流程，允许条件分支和人工处理节点。
- 批处理支持按查询选择资产、样本试跑、结果预览、差异比对、正式运行及输出撤回/版本恢复。
- 任务记录固定输入版本及规则版本；源资料发生变化时标记冲突，避免用旧结果覆盖新资料。
- 支持并发限制、组织配额、暂停、取消、超时、失败重试和从可重用检查点继续处理。
- 批次报告包含成功、失败、跳过、待复核及实际发布结果，保留逐资产的错误原因。
- 规则更新后由责任人选择重跑范围；重跑结果发布时更新相关索引并通知下游。

示例：合同统一抽取双方、金额、期限并标注缺失字段；制度文档按章节分块并关联有效期；含个人信息的资料生成脱敏服务版本。以上为讨论用例，不代表已确认业务规则。

### 5.5 数据治理与知识资产目录

- 建立统一资产 ID、分类、业务主题、元数据字典及生命周期。
- 最少记录名称、组织、责任人、来源、类型、版本、业务时间、密级、权限策略、有效期、状态及关联业务对象。
- 建立原始文件—处理结果—分块—索引—页面—接口/下游输出的血缘关系。
- 对完整性、准确性、可解析性、重复率、时效性和抽取质量进行校验和统计。
- 支持问题指派、人工修订、复核、重处理和质量闭环。
- 原件、标准内容和索引分别管理保留策略；索引可以重建，原件删除需受审批/保留规则控制。
- 删除、停用及源端撤权应传播至在线服务和索引；下游副本通过约定协议同步处理并报告状态。

### 5.6 权限与安全

- 对接集团 SSO、组织和用户体系；同步离职、调岗及组织关系变化。
- 支持空间、知识库及按需文档级授权；结合组织、角色、用户组、密级、业务范围和有效期判断访问。
- 明确源权限、集团规则和本平台授权的关系；工作建议为多重约束取交集，例外共享需批准。
- 将检索、正文阅读、预览、原件下载、导出、编辑、删除、处理、共享等操作分开授权。
- 权限过滤覆盖搜索、问答、缓存、API、MCP、引用和文件访问；摘要、向量及 Wiki 等派生内容继承来源限制。
- 多来源知识聚合的输出采用明确的敏感等级和发布审核策略，不能因生成新文档降低访问限制。
- 权限撤销后重新校验受控访问；临时签名链接设置适当期限，明确已导出副本的控制边界。
- 源系统凭据、服务账号、模型密钥分级保管；不因拥有连接器权限就允许读取其全部数据。
- 记录查看、下载、共享、规则变更、处理及管理操作；审计日志可对接集团审计体系。
- 各密级资料可使用的模型、解析服务和网络出口受政策约束；外部模型是否允许由集团确认。

### 5.7 知识消费与服务

- 提供按权限的全文、语义及元数据检索，支持组织、类型、来源、时间和业务主题筛选。
- 支持原文预览、来源定位、版本及血缘查看。
- 支持智能问答与引用，无法可靠回答时提示证据不足；仅使用当前授权内容。
- 提供文档/资产查询、标准内容读取、结构化抽取结果及检索服务 API。
- 支持处理完成、内容变更、删除和权限变化通知，保证消息可重试和幂等消费。
- 提供服务账号、接口配额和访问范围管理。

Agent 自动执行、MCP 对外开放和知识图谱作为后续可选能力，需独立定义工具权限与业务价值。

### 5.7.1 面向下游的 Open API

开放能力与接口范围详见 [Open API 方案](./GROUP_UNSTRUCTURED_DATA_PLATFORM_OPEN_API.md)。

- 开放授权资产目录、元数据、版本与业务对象关联查询。
- 提供发布后的正文、表格/图片等产物、来源定位、预览和按权限的原件下载。
- 提供全文/语义/混合检索，支持资源范围及允许的元数据筛选。
- 提供标准业务字段、Schema、质量/复核状态、数据产品查询及受控批量交付。
- 按需提供单轮/多轮知识问答、流式回答与原文引用。
- 提供同步基线、增量游标、变更订阅、失效/删除/撤权通知与交付回执。
- 对获批系统提供授权管道调用、异步任务状态、报告、取消及重试。
- 对批准的生产者提供资料上传、入库、自有元数据更新和删除申请。
- 提供授权质量、血缘、纠错反馈、访问申请及应用自身用量查询。
- 区分系统身份和代用户身份，分别绑定应用、用途、能力、资源范围与配额。
- 明确版本、幂等、条件更新、部分成功、限流、错误码和开发者接口规范。
- 异步结果读取、导出下载和引用访问重新校验当前权限；已交付副本通过下游契约处理失效。

不向普通下游默认开放集团组织管理、强制规则修改、源权限管理、源系统凭据、任意 SQL、存储路径读取或平台全量审计。

### 5.8 调度与运营

- 展示连接器、同步水位、管道、批次、队列及失败任务。
- 支持组织资源配额、并发公平性及大任务限流，避免一个组织占满平台资源。
- 统计资产量、处理量、质量、更新时效、检索使用、模型调用成本及组织使用情况。
- 提供日志、指标、告警、备份恢复及灾难恢复机制。

## 6. 集成边界

| 对接对象 | 从对方获取 | 向对方提供 | 首要确认项 |
| --- | --- | --- | --- |
| 集团统一身份平台 | 用户、组织、用户组、身份认证 | 应用接入及授权审计信息 | 协议、同步和权限权威来源 |
| 集团数据中台 | 主数据、分类标准、业务标识及相关数据 | 非结构化目录、血缘、质量及抽取结果 | 元数据规范和数据交换协议 |
| 集团数据门户 | 门户导航、统一登录及交互规范 | 授权资产目录、检索入口、预览和申请流程 | 嵌入方式、权限传递和目录同步 |
| 飞书云文档与知识库 | 内容、目录、附件、身份映射、源权限及可用变更信息 | 同步状态、原文回跳；经确认的结果发布 | 租户/应用授权、资料范围、API 与事件能力、权限映射 |
| 上游业务系统 | 文件、正文、附件、业务元数据、版本与权限 | 接入/处理状态及错误反馈 | 增量、删除、撤权、限流与对账 |
| 下游业务系统 | 消费范围和格式约定 | 标准内容、抽取结果、检索及变更通知 | 授权、版本、幂等与撤销协议 |
| 基础设施与审计 | 存储、密钥、监控及安全策略 | 日志、事件、指标 | 部署、容量及留存规范 |

每个集成应明确责任方、接口契约、对象 ID、认证方式、同步频率、错误补偿及验收样例。同步失败时，不应无限保留已撤销的访问权限；应制定对账与失效策略。

## 9. 验收场景建议

1. 两个试点组织各自接入和维护资料，未授权用户不能通过搜索、问答、预览或文件链接读取对方内容。
2. 组织共享指定知识库后，目标用户能按授予权限使用；撤销后在约定时间内停止新的访问。
3. 接入一批具有代表性的资料，原件、标准内容、处理规则、版本与定位信息可逐项追溯。
4. 使用统一规则批处理样本，产生逐文档结果和错误报告；重复提交不制造重复资产。
5. 中断处理后可恢复；源资料更新不会被旧批次输出覆盖；失败对象能单独重试。
6. 修改处理规则后试跑并对比结果，再发布新版本；服务索引及下游接收版本一致。
7. 源端删除或撤权后，平台与下游按约定传播，并可查看未完成的补偿任务。
8. 门户展示授权目录，调用标准内容或检索接口；结构化抽取结果可关联集团业务对象。
9. 知识问答引用可追溯到允许访问的原文版本；聚合内容不会泄露未授权来源。
10. 运维人员能查看任务和告警，普通运维权限不自动赋予业务资料读取权。
11. 飞书指定范围的文档和目录可同步为资产并回跳原文；重复采集与跨目录引用不会造成无控制的重复资产或权限合并。
12. 飞书更新、移动、撤权和删除可按约定处理；事件丢失可通过对账修复，接口失败不造成误删或权限放宽。
13. 下游 API 按应用和用户范围授权，重试不重复生成任务，旧版本不覆盖新结果；异步结果在撤权后不可继续读取。
14. 缓存/复制型下游能从基线衔接增量，收到撤权/删除通知并报告处置状态；失权通知不泄露受限内容。

验收应覆盖不同格式、密级、组织、权限和异常情况，不能仅以文件上传成功或模型回答成功作为完成标准。

## 10. 候选平台参考（非二开决策）

以下基于当前本地源码的初步核对，尚未经过部署验证或完整差距评估。

| 能力 | 当前可复用基础 | 集团目标需要进一步评估或新增 |
| --- | --- | --- |
| 知识应用 | 知识库、检索、问答、引用、Wiki | 集团资产目录及业务主题模型 |
| 组织权限 | 空间角色、组织共享、资源访问校验、API Key | 集团多级组织、SSO/权限映射、文档级策略 |
| 数据接入 | 文件上传和已有数据源连接器 | 集团专有连接器、增量对账、删除及撤权协议 |
| 知识处理 | 解析、分块、索引、自动标签、批量重新解析 | ELT 原始区、统一规则中心、可配置管道、脱敏和字段模板 |
| 加工管理 | 异步任务、队列管理及部分版本机制 | 完整血缘、批次输入快照、质量闭环和发布/回放策略 |
| 存储服务 | 本地和对象存储、多后端及受控文件访问 | 集团原始/标准/服务区、保留政策、目录与下游契约 |
| 运行治理 | 日志、追踪、任务与权限审计基础 | 集团 SLA、灾备、组织配额、资源与成本运营 |

现有批量标签、删除、下载与重新解析不等同于通用业务规则引擎；现有版本机制也不等同于完整 ELT 数据血缘和加工结果回放。后续应通过代表性样本与接口验证决定复用范围。
